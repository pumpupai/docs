Pump Up is framework-agnostic. The SDK is the same regardless of which orchestrator your agent runs on, and most integrations are under ten lines of code: import the SDK, call `approvals.create` (or `info_requests`, `handoffs`, `routing`) at the point where you need a human, branch on the result.

These pages show the idiomatic integration point for each framework — the right callback, node, or gating step — using the same canonical claim-approval example so you can compare them side by side.

## Don't see your framework?

Pump Up's SDK works anywhere your agent code runs — there's no requirement to use one of these frameworks. The canonical example on each integration page is small enough to translate to whatever orchestrator you're on.

## What's the same across every integration

- **Queue names live on the server.** Your code references queues by string. Routing, reviewers, and SLAs are configured in the [dashboard](https://app.pumpup.dev), not in your code.
- **`params` is the data the reviewer sees.** Pass realistic field names; they show up on the ticket.
- **Calls block by default.** `approvals.create` waits for the reviewer (or the SLA). For long-running approvals, use the async pattern. See [Approvals](/concepts/approvals).
- **Decisions land in the audit trail.** No extra wiring required.
