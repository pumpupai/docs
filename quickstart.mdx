Pump Up supports most programming languages and also has dedicated bindings to popular agent frameworks. This quickstart, walks you through sending your first approval request. By the end, you'll have an agent that proposes an action, waits for a human reviewer, and acts on the response.

## Prerequisites

- A Pump Up account and an API key from the [dashboard](https://app.pumpup.dev)
- Python 3.9 or later
- A reviewer queue configured in the dashboard (the quickstart uses one named `approve_claim`)

## 1. Install the SDK

<CodeGroup>

```bash pip
pip install pumpup
```

```bash uv
uv add pumpup
```

```bash poetry
poetry add pumpup
```

</CodeGroup>

## 2. Set your API key

```bash
export PUMPUP_API_KEY="pk_live_..."
```

## 3. Send an approval request

Save this as `quickstart.py` and run it.

```python
import os
from pumpup import PumpUp

pumpup = PumpUp(api_key=os.environ["PUMPUP_API_KEY"])

result = pumpup.approvals.create(
    queue="approve_claim",
    params={
        "amount_usd": 8400,
        "claim_id": "CLM-83472",
        "reason": "Lost package — customer provided tracking and photos.",
    },
)

if result.status == "approved":
    print(f"Approved by {result.decided_by} — paying out claim {result.params['claim_id']}")
elif result.status == "rejected":
    print(f"Rejected: {result.notes}")
elif result.status == "edited":
    print(f"Approved with edits — new amount ${result.params['amount_usd']}")
else:
    print(f"Request ended with status: {result.status}")
```

The call blocks until a reviewer responds or the queue's SLA expires. While it waits, the reviewer assigned to the `approve_claim` queue sees a ticket with the claim details and three actions: approve, reject, or edit.

## 4. What just happened

- **`queue="approve_claim"`** told Pump Up which routing rules, reviewers, and SLA to apply. Queues are configured server-side; your code only references them by name.
- **`params`** carried the data the reviewer needs to decide. Anything in this dictionary is shown on the ticket.
- **`result`** holds the reviewer's decision. `status` is one of `approved`, `rejected`, `edited`, or `timed_out`. If the reviewer edited the request, `result.params` reflects their changes.
