---
title: "Approvals"
description: "Pause an agent on a sensitive action, send a proposed action to a human, and resume with the decision."
---

Use an approval when your agent wants to take an action that needs a human's sign-off. 

Common use-cases are issuing a refund, sending an outbound email, releasing a payout, or destructive actions on your database or system of record. Pump Up routes a ticket to the right reviewer, and returns their decision so your agent can act on it.

## The simplest example

<CodeGroup>

```python Python
import os
from pumpup import PumpUp

pumpup = PumpUp(api_key=os.environ["PUMPUP_API_KEY"])

result = pumpup.approvals.create(
    queue="approve_claim",
    params={
        "amount_usd": 8400,
        "claim_id": "CLM-83472",
    },
)

if result.status == "approved":
    process_claim(result.params["claim_id"])
```

```python Tools (LangChain)
import json, os
from langchain.callbacks import HumanApprovalCallbackHandler
from pumpup import PumpUp

pumpup = PumpUp(api_key=os.environ["PUMPUP_API_KEY"])

def pumpup_approver(serialized_input: str, **_) -> bool:
    args = json.loads(serialized_input)
    result = pumpup.approvals.create(
        queue="approve_claim",
        params={
            "amount_usd": args["amount_usd"],
            "claim_id": args["claim_id"],
        },
    )
    return result.status in ("approved", "edited")

approval = HumanApprovalCallbackHandler(
    approve=pumpup_approver,
    should_check=lambda s: s.get("name") == "process_claim",
)

executor.invoke({"input": "Process CLM-83472, $8400."}, callbacks=[approval])
```

</CodeGroup>

`approvals.create` blocks until the reviewer responds or the queue's SLA expires.

## What the reviewer sees

The reviewer assigned to the `approve_claim` queue gets a ticket with:

- The fields you sent in `params`, rendered with the queue's display schema
- Three actions: **Approve**, **Reject**, or **Edit and approve**
- The agent's reasoning, if you passed it in `params`
- A free-text note field for the reviewer's reasoning

## What `result` contains

| Field | Type | Description |
| --- | --- | --- |
| `status` | string | One of `approved`, `rejected`, `edited`, `timed_out` |
| `params` | dict | The original `params`, with any reviewer edits applied |
| `decided_by` | string | The reviewer's user ID or email |
| `decided_at` | datetime | When the decision was made |
| `notes` | string | Free-text note the reviewer added, if any |

When `status` is `edited`, treat the response as approved but use `result.params` rather than the values you sent.

## Common patterns

### Threshold-gated approvals

Only call Pump Up when the action crosses a policy threshold. The agent handles the easy cases; humans see only the ones that need them.

```python
if amount_usd > 1000:
    result = pumpup.approvals.create(
        queue="approve_claim",
        params={"amount_usd": amount_usd, "claim_id": claim_id},
    )
    if result.status != "approved" and result.status != "edited":
        return
    amount_usd = result.params["amount_usd"]

process_claim(claim_id, amount_usd)
```

### Handling timeouts

If the SLA expires before a reviewer responds, `status` is `timed_out`. The fallback behavior — escalate, auto-reject, or hold — is configured on the queue.

```python
if result.status == "timed_out":
    log.warn(f"Approval timed out for claim {claim_id}")
    return
```
