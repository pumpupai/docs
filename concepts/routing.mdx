---
title: "Routing"
description: "Let a human pick the next step in the workflow when the agent shouldn't decide on its own."
---

Use a routing request when the agent has reached a branch point and a human should choose which path to take. Unlike approvals, the human isn't sanctioning a proposed action — they're selecting from a set of options.

Routing is most natural in graph-based agents — LangGraph, Mastra, Temporal, anything with explicit conditional edges between steps — where the human's choice maps directly onto which branch fires. You can use it from a plain agent loop too; you just call `routing.create` in your code and switch on `result.choice`.

## The simplest example

<CodeGroup>
```python Python
import os
from pumpup import PumpUp

pumpup = PumpUp(api_key=os.environ["PUMPUP_API_KEY"])

result = pumpup.routing.create(
    queue="discount_path",
    params={
        "deal_id": "DEAL-91204",
        "requested_discount_pct": 28,
        "arr_usd": 145000,
    },
    options=[
        {"value": "approve_as_is", "label": "Approve at 28%"},
        {"value": "counter_at_20", "label": "Counter at 20%"},
        {"value": "escalate_to_vp", "label": "Escalate to VP of Sales"},
        {"value": "decline", "label": "Decline"},
    ],
)

next_step = result.choice
```

```python Tools (LangGraph)
import os
from langgraph.graph import StateGraph, END
from pumpup import PumpUp

pumpup = PumpUp(api_key=os.environ["PUMPUP_API_KEY"])

def pick_discount_path(state):
    result = pumpup.routing.create(
        queue="discount_path",
        params={
            "deal_id": state["deal_id"],
            "requested_discount_pct": state["pct"],
            "arr_usd": state["arr"],
        },
        options=[
            {"value": "approve_as_is", "label": f"Approve at {state['pct']}%"},
            {"value": "counter_at_20", "label": "Counter at 20%"},
            {"value": "escalate_to_vp", "label": "Escalate to VP"},
            {"value": "decline", "label": "Decline"},
        ],
    )
    return {**state, "next": result.choice}

graph = StateGraph(dict)
graph.add_node("route", pick_discount_path)
graph.set_entry_point("route")
graph.add_conditional_edges("route", lambda s: s["next"])
```
</CodeGroup>

The reviewer sees the deal context and picks one option. Their selection comes back as `result.choice`.

## What `result` contains

| Field | Type | Description |
|---|---|---|
| `status` | string | `decided` or `timed_out` |
| `choice` | string | The `value` of the option the reviewer picked |
| `decided_by` | string | The reviewer's user ID or email |
| `notes` | string | Free-text note the reviewer added, if any |

## Common patterns

### Branching agent flows

Use the returned `choice` to drive a switch in your agent code.

```python
match result.choice:
    case "approve_as_is":
        send_contract(deal_id, discount_pct=28)
    case "counter_at_20":
        send_counter(deal_id, discount_pct=20)
    case "escalate_to_vp":
        pumpup.handoffs.create(queue="vp_review", params={"deal_id": deal_id})
    case "decline":
        send_decline(deal_id)
```

### Dynamic options

Compute `options` from your agent's state so the reviewer only sees relevant choices.

```python
options = [{"value": "approve_as_is", "label": f"Approve at {pct}%"}]
if pct > 20:
    options.append({"value": "counter_at_20", "label": "Counter at 20%"})
if arr > 100_000:
    options.append({"value": "escalate_to_vp", "label": "Escalate to VP"})
```
